# REPORT: signal-ml-lab (P17)

Status: exploratory, not pre-registered. Every number below is read
from a committed results file and regenerated by the command named
next to it. Synthetic data only throughout.

## Background

Jesun's two 2023 AIP Conference Proceedings papers described wavelet
features plus a neural network for fabric defect detection. This repo
rebuilds that method in public, from zero, in NumPy: a hand-written
Haar transform (two levels, 12 energy and summary features) feeds a
12-16-2 ReLU/softmax network trained by full-batch gradient descent.
The papers' data and reported metrics are not used, so this is a
rebuild of the method, not a replication of its results. TensorFlow
was planned for a depth track but was never importable in the build
environment; every TensorFlow item shipped as a labelled NumPy or
standard-library substitute (docs/decisions/0001).

## Method

- Data: a seeded synthetic recipe (level-1-learn/signal_ml.py
  make_dataset). Signals have 64 samples: sine mixtures plus Gaussian
  noise (sigma 0.05); a defect adds a local bump of amplitude 0.8 to
  1.4, width 3 to 6. Train seed 0 (2,400 signals, balanced), test seed
  42 (500 signals, balanced). Train and test share the generator.
- Model: the Build artifact level-2-build/artifacts/model/1 (200
  epochs, lr 0.05, seed 1), hash-verified on load.
- Baselines (same features or same network and budget): majority class,
  one-feature threshold, logistic regression on the 12 features, the
  same network on the raw 64 samples, the same network on 12 FFT band
  energies (level-3-deep/rigor.py).
- Uncertainty: Wilson 95% intervals on every accuracy; 10 training
  seeds; 5 fresh train and test data seeds.
- Compute and versions: CPU only. The v1.0 runs (2026-11-05) were on
  the Muse VM, Python 3.12.3, NumPy 1.26.4; the rigor pass
  (2026-11-07) adds new numbers only and reproduces byte for byte with
  NumPy 2.4.5 on Python 3.12.3 (checked 2026-11-08) and in CI.

Further misses the rigor pass found: the model fails under noise it was
not trained on (false alarm rate 0.705 at sigma 0.1, 1.0 from sigma
0.2), and 7 of the 8 test misses are width-4 bumps aligned to a level-2
Haar block (12 of 250 test defects are aligned). The v1.0 headline also
measures an under-trained network: longer training reaches 1.000.

## Threats to validity

- Synthetic data, one shared generator for train and test; no real
  fabric data, no comparison with the 2023 papers' numbers.
- The task is close to separable: one threshold on one feature gets
  0.934.
- One CPU machine; latencies and loader timings are single runs; the
  assigned BlackBox GPU node was not used and no real edge device was
  measured.
- One artifact version only, with no multi-version migration or
  rollback test.
- The Build weights are not bit-identical across NumPy versions:
  re-running level-2-build/run_build.py under NumPy 2.4.5 (2026-11-08)
  gives a different weights hash with the same accuracy and sizes. Every
  result here evaluates the committed artifact (weights SHA-256
  93e2f8c1...), so CI runs Build and Deep end to end but does not diff
  their outputs.
- The NumPy artifact format is local to this repo and the API is a
  localhost study server (no auth, no TLS, no rate limit).

## Field profile (ML and AI research) and verdict

Baselines under the same budget and uncertainty on the headline are
met. Ablations (removing one part of the method at a time) are not
done; input substitutions are not ablations. Compute, data and versions
are recorded, though the results files carry the v1.0 NumPy version
only. With no locked plan, the profile cannot be met under the
standard, so the verdict is Functional, not pre-registered.

## Conclusion

The method is rebuilt cleanly and runs end to end, from features to a
served, versioned, quantized model, with every number reproducible in
seconds. As science the claim stays thin: on this synthetic task,
wavelet features do not beat FFT features, and the model breaks under
unseen noise. The next result that matters is a locked run on real
fabric data.

## Remaining gaps and exactly what each needs

(From the 2026-11-07 review and the ROADMAP.md v1.1 backlog, merged.)

1. **Validation on real data.** Needs a public 1-D or image fabric-defect dataset (for example AITEX or TILDA, which are images, so rows or texture profiles would have to be extracted into 1-D signals) and a written extraction protocol. CPU is enough at this model size; minutes per run.
2. **Comparison with the 2023 papers.** Needs full citations for the two 2023 AIP Conference Proceedings papers (PROPOSAL.md), their datasets and their reported metrics, then the same metrics computed here. No compute beyond the item above.
3. **Related-work survey.** Needs a literature pass (wavelet and FFT features for defect detection, 1-D CNN baselines) of about 10 to 20 papers, written into PROPOSAL.md. No compute.
4. **Distribution shift.** Needs a held-out generator variant (different base frequencies, drift, non-Gaussian noise) and training with noise augmentation over sigma 0.05 to 0.3. CPU, under a minute with rigor.py's generator.
5. **Fix for the alignment blind spot.** Needs a shift-invariant transform (undecimated or stationary Haar transform, or features at both even and odd offsets) and a re-run of the width-4 start sweep. CPU, seconds.
6. **Paired model comparison.** Needs McNemar tests on the shared test set or a bootstrap over several fresh test sets. CPU, seconds; can be added to rigor.py.
7. **Latency statistics.** Needs warm-up plus repeated runs (for example 30 runs of 1,000 calls) with medians and intervals, ideally on a second machine. CPU, a few minutes.
8. **TensorFlow track.** Needs an environment where TensorFlow imports, then SavedModel, TF Serving, TFLite conversion and the TF Profiler. A real edge result also needs real edge hardware (for example a Raspberry Pi or a microcontroller board).
